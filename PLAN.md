# План проекта: ИИ-консультант МТС EnergyTool

Онлайн-этап: 09.11 - 16.11.2026. Лимит: 5 сабмитов в день, 20 минут на прогон, 8 CPU / 16 ГБ.
Архитектура и обоснования: [SOLUTION.md](SOLUTION.md). Исследование и замеры: [RESEARCH_SUMMARY.md](RESEARCH_SUMMARY.md).
Журнал решений для агентов: agent-dump/research/critique/decisions.md.

## Принцип

Одно ядро `advisor_core` (только разрешенные пакеты) для сабмита и для веб-сервиса. Сначала балл судьи, потом продукт вокруг того же ядра. Сабмиты на платформу отправляет только владелец проекта, агенты готовят ZIP.

## Этап 0 (09.11, сделано): исследование

- Обзор аналогов и работ, RAG-лаборатория (88 вопросов), эмулятор платформы на GPU и реплика судьи, выбор стека с бенчмарками, проектирование диалога, три раунда взаимной критики.
- Итог: конфигурация K1 (гибрид + приор H2 + доменный граф + реранк с таймаутом + один вызов v3).
- Сравнение иерархических и графовых архитектур: берем гибрид + приор H2 + доменный граф без LLM (MRR 0.881 → 0.895), графовые и RAPTOR отвергнуты по замерам.

## Этап 1 (10.11): ядро и первый сабмит

Задачи:
- Перевести проект на Python 3.13 (`.python-version`, `requires-python >=3.12,<3.14`).
- `advisor_core`: загрузка базы из zip, разделы с крошками, эмбеддинги пакетами, bm25s со стеммингом, гибрид, реранк с таймаутом и RRF, промпт v3 + 4 примера, пост-проверка.
- `solution.py`: probe возможностей прокси, дедлайн 18 мин, предзаполненный CSV с атомарной записью, ступени деградации, ретраи 429/5xx с ограничением.
- `build_zip.py`: плоские корневые модули + requirements.txt из разрешенного списка; проверка в контейнере с теми же пинами (Python 3.12/3.13, 8 CPU / 16 ГБ, без сети кроме эмулятора).
- Eval: реплика судьи, golden-18, поведенческие метрики, регрессия поиска.

Сабмиты дня: K1. Если прокси не держит реранк - K2.
Готово, когда: балл судьи > 0 и выше baseline, прогон на эмуляторе укладывается в 20 минут с запасом на 300 вопросов.

## Этап 2 (11.11-12.11): качество ответов

- Разбор полярности ("нет" против "может иметь смысл") и возврата к теме на 27B по результатам сабмитов.
- Перекалибровка порогов нецелевых вопросов на реальных оценках.
- Независимые эталоны для 44 дополнительных вопросов (свежий агент, не видевший промпт).
- Приор H2 и доменный граф в ядро; проверить прирост на реальных сабмитах.

Сабмиты: по одной гипотезе, последний сабмит дня - лучшая известная конфигурация.

## Этап 3 (12.11-14.11): продукт

- API: FastAPI, SSE вручную, `/widget/session` с подписанным токеном, `/chat`, `/leads` (идемпотентно), `/admin` (все сессии и заявки), `/healthz`, `/readyz`.
- Данные: PostgreSQL (sessions, messages, leads, consents, outbox), Alembic; Valkey для лимитов и блокировок.
- Диалог: параллельный мини-разбор, эффекты E0-E6 с юнит-тестами, форма контакта с согласием, резюме для менеджера (JSON + текст).
- Доставка: outbox-воркер, Log/Webhook-адаптеры, уведомление без ПДн.
- Фронтенд: loader.js + iframe, React-чат, "Новый диалог", быстрые подсказки, режим отладки по токену.

Готово, когда: основной сценарий от первого вопроса до заявки проходит в браузере, история всех сессий видна в админке.

## Этап 4 (14.11-15.11): прод-качество

## Риски

| Риск | Что делаем |
|---|---|
| Прокси не отключает thinking | Probe + запасные настройки + строгий режим; дедлайн и ступени деградации |
| Нет json_schema | Сабмиту не нужен; в вебе json_object + pydantic + один повтор |
| `/rerank` медленный или иной формат | Таймаут, K2 без реранкера (ничья по качеству) |
| Переобучение под 18 эталонов | Независимые эталоны, правки промпта только с проверкой на всех срезах |
| Слабый локальный судья | Выбор между кандидатами по сильной модели на golden-18 и реальным сабмитам |
| GPU-ноутбук выключат | Эксперименты с чекпоинтами, команды перезапуска в gen-lab.md |
