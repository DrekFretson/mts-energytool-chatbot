# МТС EnergyTool: ИИ-консультант (MVP)

Консультант для сайта: понимает задачу клиента, отвечает по базе знаний, собирает заявку с резюме для менеджера. Одно ядро `core/` работает и в сабмите для LLM-судьи, и в веб-чате.

## Запуск

База знаний не хранится в репозитории: положите архив в `data/knowledge-base.zip`.

```bash
cp .env.example .env
```

```bash
docker compose up --build
```

Чат: http://localhost:8000. История сессий: http://localhost:8000/admin (токен `DEBUG_TOKEN`).

Без `LLM_BASE_URL` поднимается заглушка `fake-llm`: сценарий проходит, но ответы ненастоящие. Для настоящих ответов укажите в `.env` любой OpenAI-совместимый сервер с `/chat/completions`, `/embeddings` и `/rerank`.

## Проверка основного сценария

1. Задать 3 вопроса: на третьем бот предложит связаться с менеджером.
2. Включить «Отладка», ввести `DEBUG_TOKEN`: под ответами появятся время и разделы базы.
3. «Связаться с менеджером»: заполнить форму тестовыми данными и дать согласие.
4. Открыть `/admin`: видны все сессии, диалоги и заявка с резюме.
5. «Новый диалог» начинает новую сессию, старая остаётся в истории.

## Архитектура

```
core/       ядро и сабмит, плоские модули, только разрешённые пакеты
  kb.py         zip -> фрагменты с крошками, разбор pandoc-таблиц
  retrieval.py  bge-m3 + BM25, реранк с откатом
  llm.py        чат, эмбеддинги, реранк, ретраи
  prompts.py    системный промпт и резюме
  pipeline.py   answer(index, history) -> {text, sources, timings, unverified_numbers}
  solution.py   точка входа платформы
  config.py     все параметры экспериментов
web/        FastAPI, SQLite, статические чат и /admin
eval/       поведенческие метрики ответа
tests/      автотесты и заглушка LLM
```

Сбой внешнего сервиса не роняет ответ: без реранкера остаётся гибрид, без эмбеддингов BM25, без LLM запасной текст. `submission.csv` создаётся сразу и переписывается атомарно, дедлайн 18 минут.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `LLM_BASE_URL`, `LLM_API_KEY` | OpenAI-совместимый сервер и ключ |
| `LLM_MODEL`, `EMB_MODEL`, `RERANKER_MODEL` | Идентификаторы моделей |
| `DEBUG_TOKEN` | Доступ к отладке и `/admin`; пустой значит отключено |
| `DB_PATH`, `KB_PATH` | SQLite и архив базы знаний |
| `PORT` | Порт на хосте, по умолчанию 8000 |
| `DATA_DIR`, `MAX_WORKERS`, `MAX_TOKENS` | Передаёт платформа в сабмите |

## Разработка

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
```

```bash
.venv/bin/python -m unittest discover -s tests
```

Сабмит:

```bash
python build_zip.py
```

Архив появится в `dist/submission.zip`. Локальный прогон на демо-вопросах (нужен запущенный сервер LLM в `LLM_BASE_URL`):

```bash
DATA_DIR=data PYTHONPATH=core .venv/bin/python core/solution.py && .venv/bin/python eval/report.py submission.csv data/demo_output.csv
```

План сабмитов: [research.md](research.md).

## Куда наращивать

| Зона | Что дальше |
|---|---|
| `core/` | Приор H2 и доменный граф в `retrieval.py`; извлекающий запасной ответ; использование `unverified_numbers` |
| `eval/` | Реплика судьи: два раунда и формула регламента; эталоны для отказов, нецелевых вопросов и инъекций |
| `web/` | Стриминг SSE; намерения вместо счётчика реплик; виджет `loader.js` + iframe; лимиты запросов; отдельный документ согласия |

Общий контракт — `pipeline.answer`. Менять его только по договорённости всех трёх зон.

## Известные ограничения

- Ответ приходит целиком, стриминга нет.
- Заявку предлагает счётчик реплик, а не разбор намерений.
- SQLite рассчитан на один экземпляр сервиса.
- Лимитов запросов нет.
- Качество ответов на Qwen3.8-27B не измерено до первого сабмита.
